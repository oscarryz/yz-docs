# Boc-typed fields of a type are dropped

`YZC-0127`

**A field with a boc type in an uppercase boc is missing from the generated struct and its
constructor.** The decided `while` dispatcher form ([`stdlib.md`](../../Questions/stdlib.md))
needs `While` to hold `cond #(Bool)` and `body #()`.

## Observed

```yz
Task: {
    action #()
    run: { action() }
}
main: {
    t: Task({ print("hi") })
    t.run()
}
```

`yzc v0.5.0-e08b58a` passes it to `go build`, which fails:

```
./main.go:19:9: cannot use std.Go(func() std.Unit {…}) (value of type *rt.Thunk[rt.Unit]) as rt.Unit value in return statement
./main.go:20:10: undefined: action
./main.go:43:16: too many arguments in call to NewTask
	have (func() rt.Unit)
	want ()
```

The `Task` struct has only its embedded `std.Cown`, and `NewTask()` takes no arguments. The caller
side is right: it passes the closure.

## Not confirmed

- Where the field is lost. YZC-0100 lists the singleton call sites that now accept
  `*ast.BocDecl{Sig != nil, Body == nil}` as a param (`lowerBodyOnlySingleton`,
  `lowerLocalBodyBoc`, `lowerBocDeclAsLocal`, `sema.collectParams`). The struct path was not read;
  it most likely skips that node shape the way those did before.
- The first `go build` error (the `run` body returning a thunk) may be a consequence of `action`
  being unknown, not a separate bug.
