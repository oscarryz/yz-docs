# `Foo.Bar()` static access is not rejected by yzc

`YZC-0082`

**`Foo.Bar()` passes every yzc check and fails at `go build`, as a raw Go error pointing at the
generated `main.go`.** The nested type itself shipped in `e047c3a`; this is what is left of the
ticket.

## Observed

```yz
Foo: { name String
       Bar: { tag String } }
main: { b : Foo.Bar(tag: "x"), print(b.tag) }
main()
```

With `yzc` built from `ccebf83`:

```
./main.go:50:30: Foo (type) is not an expression
yzc run: go build: exit status 1
```

The same gap appears when an inner field initializer references an outer field, as in `n: name`:

```
./main.go:53:54: undefined: name
```

## What already works

- `Foo: { Bar: { ... } }` with `f.Bar(...)` compiles and runs through `yzc run`, including inner
  methods that use the inner type's own fields.
- An inner method body can read an outer field: `both: { name + tag }` printed `alice-t`.
- Golden test `92_struct_nested_type` covers `alice.Bar()` and `bob.Bar()`.
- The design is decided in [spec 04](../../../spec/04-type-system.md), "Nested Type Declarations":
  the type is bound to the instance, and its methods can read but not write the outer instance's
  fields.

## Original checklist

- [x] *design* — decide whether inner type bodies can reference outer instance fields (path-dependent vs. self-contained)
- [x] Sema: recognize uppercase struct-literal inside struct boc as concrete associated type definition
- [ ] Sema: `f.Bar()` resolves to the inner type; enforce no `Foo.Bar()` static access (resolution works; enforcement is missing)
- [x] Lowerer: emit inner type as package-level Go struct; `f.Bar()` → constructor call
- [x] Golden test: `Foo: { Bar: {} }` + `f.Bar()` compiles and runs

## Not confirmed

- Whether a write to an outer field from an inner method is rejected, as the spec's "read (but not
  write)" requires. It was not tested.
- The empty-bodied `Foo: { Bar: {} }` form. The golden test and the repros use inner types with
  fields or methods.

## Fix

Have sema reject a struct-outer nested type reached through the outer type name, with a Yz-level
diagnostic, and add an error conformance test. The inner field initializer needs a diagnostic too.
