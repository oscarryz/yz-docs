# A type's methods are not visible on its instances inside its own methods

`YZC-0128`

**A method cannot call a method on another instance of its own type.** The decided `while`
dispatcher form ([`stdlib.md`](../../Questions/stdlib.md)) recurses this way: `run` calls
`While(cond, body).run()` so each iteration is a fresh instance.

## Observed

```yz
Counter: {
    n Int
    count: {
        print("n ${n}")
        n > 0 ? {
            next: Counter(n - 1)
            next.count()
        }, {}
    }
}
main: {
    c: Counter(3)
    c.count()
}
```

With `yzc v0.5.0-e08b58a`:

```
error: type Counter has no field "count"
 --> main.yz:7:18
```

`c.count()` in `main` resolves. Calling `count()` on the same instance (plain `count()`) also
compiles. The local is used instead of `Counter(n - 1).count()` to stay clear of YZC-0126.

In the `while` experiment, with `While` declared in a `while.yz` file, the call from the lowercase
`while` dispatcher in the same file (`w: While(cond, body); w.run()`) failed with the same error.
Moving `While` into `main.yz` fixed that call but not the one inside `run`. Whether that first
failure is this bug or the file-wrapper unwrap (YZC-0122) was not narrowed down.

## Not confirmed

- The cause. Most likely the type's methods are added to its type only after its method bodies are
  analyzed, so inside them the type has fields but no methods. The sema code was not read.
