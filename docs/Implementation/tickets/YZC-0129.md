# A singleton and a type whose names differ only in case fail to build

`YZC-0129`

**`greeter` and `Greeter` in the same package produce two Go declarations named `Greeter`.** The
pairing is not an edge case: it is the decided thin-dispatcher pattern for library functions
([How to use utility functions](../../Questions/solved/How%20to%20use%20utility%20functions.md)),
where a lowercase `while` dispatches to an uppercase `While`.

## Observed

```yz
Greeter: {
    name String
    greet: { print("hi ${name}") }
}
greeter: {
    g: Greeter("bob")
    g.greet()
}
main: {
    greeter()
}
```

`yzc v0.5.0-e08b58a` passes it to `go build`, which fails:

```
./main.go:57:5: Greeter redeclared in this block
	./main.go:5:6: other declaration of Greeter
./main.go:71:20: Greeter.Call undefined (type Greeter has no field or method Call)
```

`type Greeter struct` is the type; `var Greeter = &_greeterBoc{}` is the singleton, its name
capitalized so it is exported.

## Fix

Give one of the two a Go name that cannot collide, for example a fixed prefix or suffix on singleton
vars. Go only lets another package reference a capitalized name, so lowercasing the singleton is
not enough on its own. Whatever the scheme, codegen has to use it at every reference site,
including the cross-package ones.
